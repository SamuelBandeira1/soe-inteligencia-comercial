Maintenance and data-pipeline scripts run locally by the analyst, not by the deployed app. The main workflow is: `incrementa_vendas_diario.py` → `atualiza_dados.py` → upload scripts.

## Summary

- `atualiza_dados.py` — main ETL: reads `data/raw/` CSV+XLSX, produces four parquets in `data/processed/`, logs quality report
- `incrementa_vendas_diario.py` — appends a monthly sales CSV into the master raw file before ETL
- `upload_dados_gdrive.py` — uploads processed parquets to Google Drive (OAuth flow, token cached in `token_gdrive.json`)
- `upload_dados_hf.py` — uploads processed parquets to Hugging Face Spaces repo
- `sync_vault.py` — syncs `.memory/` session notes to an Obsidian vault at `D:/brain_organizer/`
- `criar_atalhos_desktop.ps1` — creates Windows desktop shortcuts for the bat scripts
- `simulacao_calibracao/` — offline propensity score calibration simulations (does not touch production engine)
- `_diagnostico_raw.py` — diagnostic helper: inspects raw data quality (prefixed `_` = ad-hoc tool)
- `_diag_meta.py` — diagnostic helper: inspects meta/forecast file
- `_review_dados.py` — diagnostic helper: reviews processed data

## Constraints

- `atualiza_dados.py` MUST be run from the project root (it adds `app/` to `sys.path` to import `config.py`)
- MUST NOT be imported by the Streamlit app at runtime
